# Workmap 设计文档

本文说明 Workmap 的设计目标、数据模型、写回机制、代码结构和几处关键取舍，供以后维护和扩展时参考。使用说明见 [功能文档](features.md)。

## 1. 目标与原则

1. **md 是唯一的数据源。** 任务、位置、日程全部写在时段笔记里，插件不另存任务数据。关掉插件，笔记照样能读，也能用别的工具处理。大模型回顾、出题读的也是同一份文件。
2. **双向同步。** 视图里的操作立刻写回 md；在编辑器里改 md，视图也会自动刷新。
3. **格式对人友好。** 任务就是标准的 `- [ ]`。元数据放在 `%%…%%` 注释里，阅读模式下不显示，实时预览中由编辑器扩展隐藏。星标和截止日期用人能直接看懂的 `★`、`📅`。
4. **不需要构建。** 只有一个 CommonJS 文件 `main.js`，直接用 Obsidian 提供的 API 和 `moment`。改完重启即可，方便随手改。
5. **样式参照 Apple 应用**（提醒事项、日历、小组件）：SF / 苹方字体、系统色、毛玻璃顶栏、iOS 开关和分段控件。

## 2. 文件与数据

### 2.1 时段笔记的识别

```js
const PERIOD_RE = /^(\d{4})\/(\d{1,2})\/(\d{1,2})-(\d{1,2})\.md$/;
```

库里所有路径符合上面格式的 md 都算一期，例如 `2026/11/18-30.md`。`parsePeriod` 会得到年、月、起止日期和 `moment` 对象。`periodFor(date)` 用来找包含某天的那一期。

新建时，文件夹是 `年/两位月`，文件名不补零（`1-10.md`）。

### 2.2 笔记结构

```
（任意前言，比如打开视图的链接）
## 周期任务        ← periodRange：到第一个 --- 或一、二级标题为止
- [ ] …
## 本期笔记        ← notesRange：每行一个 [[链接]]
- [[2026/11/18-30/某篇笔记|某篇笔记]]
---
## 19             ← listDays / dayRange：到下一个一、二级标题为止
- [ ] …
## 18
…
```

- 用 `ensureDay(lines, day)` 定位或新建某天的小节。新建时插在第一个「日期更小」的小节前面，所以新的一天在上面。
- 新任务通过 `insertTaskBlock` 加入当天：先替换空的 `- [ ]` 占位行；没有的话，接在最后一个任务（及其备注）后面；当天还没有任务时，放在小节开头（旧笔记里的 `习惯：` 行之后）。

### 2.3 任务行

`parseTaskLine` 把一行解析成：

```js
{ line, raw, done, cancelled, doing, text, level, due, x, y, id, parent, slot, since }
```

状态：`[ ]` 未开始，`[/]` 进行中（`doing`），`[x]` 完成，`[-]` 已取消（`done` 和 `cancelled` 都为真）。`[>]` 是已顺延，不算任务。

解析顺序：先剥掉 `%%k:v%%` 元数据，再取出 `📅 日期` 和 `★` 星标，剩下的就是 `text`。整行加粗的 `**text**` 按三星处理（兼容旧笔记）。

`formatTask` 按固定顺序写回：

```
- [ ] 文本 ★★ 📅 YYYY-MM-DD %%id:…%% %%p:…%% %%t:…%% %%c:…%% %%m:x,y%%
```

任务下方的缩进行（`countChildren`）是备注。`collectTasks` 读取时会去掉公共缩进；`noteLines` 写回时统一缩进两个空格。

`raw` 记录解析时的原始行文本，写回时用它定位（见 4.1）。

### 2.4 四象限坐标

位置存成 `%%m:x,y%%`（0–100），象限由坐标决定：

| 象限 | 条件 | 标题 | x | y 范围 |
| --- | --- | --- | --- | --- |
| 1 | x > 50 且 y < 50 | 马上做 | 75 | 4–46 |
| 2 | x ≤ 50 且 y < 50 | 排时间做 | 25 | 4–46 |
| 4 | x > 50 且 y ≥ 50 | 尽快处理 | 75 | 54–96 |
| 3 | x ≤ 50 且 y ≥ 50 | 少做或不做 | 25 | 54–96 |

早期版本是自由摆放的坐标图，现在改成了列表，但坐标格式没变：

- x 只用来判断象限；
- y 既用来判断象限，也决定象限内的顺序（`quadList`：未完成在前，然后按 y、x、行号排）；
- 拖动排序时，`reorderPatches` 把目标象限的可见任务在 `[lo, hi]` 之间重新等距排开（`spreadY`），只改真正变了的行；
- 新任务用 `endPos`，放在当前最大 y 再加 2（不超过 hi），也就是排在末尾，不动其他行。

这样旧笔记不需要迁移，手写的坐标也能被正确归入象限。

### 2.5 周期任务与每日任务的关联

周期任务第一次被关联时，`ensurePeriodId` 给它分配 `%%id:pxxxx%%`（`p` 加 4 位随机字符）。每日任务用 `%%p:pxxxx%%` 指向它。进度 = 所有关联每日任务中完成的个数 / 总数，统计范围是当前这份笔记的所有日子。

### 2.6 本期笔记

长内容单独存成文件，放在 `年/月/起-止/`（和时段笔记同名的文件夹），时段笔记的 `## 本期笔记` 里每行一个链接。这样笔记里的标题和 `---` 不会打乱时段笔记。

- `notesOf` 列出本期笔记：先是小节里的链接（按顺序），再是文件夹里没登记的文件。
- `strayBlocks` 找出不属于前言、周期任务、本期笔记、任何一天的内容（通常是直接粘贴进来的），`takeStray` 把它们拿出来，`archiveStray` 存成新文件并换成链接。
- AI 生成的笔记带 `workmap: ai-review` / `ai-quiz` 属性，再生成时不会喂回去。

### 2.7 插件设置（`data.json`）

```js
{
  hideDone, slots, theme, size,
  hideTips,                 // 操作提示是否已关闭
  fx,                       // 趣味动画开关
  sky,                      // 星空背景开关
  zone, usZone,             // 所选时区（us / hk / paris，空表示系统时间）和美国的具体时区
  carryHold,                // 切时区跳到的新日期：这一天先不自动顺延
  carryStart,               // 顺延起点 YYYY-MM-DD，早于它的不顺延；空 = 只看上一期
  carryMode,                // 顺延后原行：mark 改成 [>]，move 删掉
  carry: { date, dismissed, items: [{ raw, text, from, since }] },  // 当天的顺延记录
  aiKey, aiBase, aiModel,   // DMXAPI 密钥、接口地址、AI 回顾 / 出题用的模型
  agentModel, agentEffort,  // 工作助理的模型和推理强度
  agentCtx,                 // 工作助理带上哪些内容：{ today, yesterday, period, notes }
  brief,                    // 今日简报缓存：{ date, at, model, text, usage }
}
```

`carry` 只用于界面提示和「顺延」标签，不是任务数据。日期一变，它就失效。

## 4. 关键机制

### 4.1 写回：按原文定位，乐观校验

所有修改都走 `plugin.mutate(file, fn)`：

```js
app.vault.process(file, data => {
  const { lines, eol } = splitLines(data);   // 保留原来的换行符
  if (fn(lines) === false) return data;      // 放弃修改
  return lines.join(eol);
});
```

`updateTask` 先确定范围（周期任务区，或者某天的小节），再在范围里找和 `task.raw` 完全相同的那一行：

- 找不到，说明笔记在渲染之后被改过。这时放弃修改，提示「笔记内容刚刚变化过」并刷新。
- 不按行号定位，是因为用户随时可能在编辑器里增删行，行号不可靠；按原文找，配合 `vault.process` 的原子读改写，能避免写错行。

`updateMany` 一次改多行（拖动排序），用 `used` 集合防止两条相同文本的任务匹配到同一行。

### 4.2 撤销

`mutate` 默认会把 `{ file, before, after }` 记进 `plugin.history`（最多 30 条）。`undo()` 取出最后一条：只有当文件内容仍然等于 `after` 时，才恢复成 `before`；否则清空历史并提示，绝不覆盖外部修改。

自动顺延、跳到今天、整理游离内容这类自动做的改动不进入撤销历史，避免 ⌘Z 撤销掉用户没意识到的操作。它们会记在 `autoWrites` 里，撤销因此失败时提示里会说明原因。

### 4.3 渲染与刷新

- 视图监听 vault 的 `modify`（只看当前文件）、`create`、`delete`、`rename`，以及 `css-change`，另外每 5 分钟刷新一次（为了跨过零点、更新当前时段）。
- 刷新有 150 ms 防抖。`busy` / `again` 两个标志保证同一时间只有一次渲染，期间来的请求合并成一次补渲染。
- 拖拽进行中不刷新，以免 DOM 被替换，拖到一半的元素消失。
- 每次渲染都整体重建 DOM（数据量小，这样最简单），并恢复滚动位置。Markdown 渲染（任务文本、备注里的链接等）挂在一个每次重建的 `Component` 上，旧的会被正确卸载。

### 4.4 拖拽

自己用 pointer 事件实现，不用 HTML5 DnD，原因是需要自定义的拖动副本和插入线，而且在 Obsidian 里表现更稳定：

1. 按下后移动超过 4 px 才算拖动。
2. 把卡片 `cloneNode` 一份，放进 `body > .pm-ghost-host`（`position: fixed`，并套用同样的皮肤），跟随指针移动；原卡片加 `is-dragsrc` 变淡。
3. 用 `elementFromPoint` 找出指针下方的时段或象限。在象限里时，按各行的垂直中点算出插入位置，并移动 `.pm-dropline`。
4. 松开后按拖动来源和目标处理：
   - 周期任务拖到象限：`splitToDay`；
   - 每日任务拖到时段：写入 `%%t%%`；
   - 每日任务拖到象限：`reorderPatches` + `updateMany`。
5. `justDragged` 在松开后 50 ms 内吞掉 click，防止拖完误触链接。
6. `pointercancel`（系统接管了手势）和拖动中按 Esc 都算取消，什么都不写。没有写文件时补一次刷新，因为拖动期间的刷新请求都被跳过了。

### 4.5 自动顺延

视图跟随今天、渲染今天时调用 `carryOver(today)`（用 `carrying` 标志防止重入）：

1. `collectCarry` 扫描本期和上一期（设了 `carryStart` 时改为起点之后的各期，且早于起点的日子不管）里日期早于今天的每一天，收集未完成的任务块（任务行和备注）。顺延时清掉日程时段，因为时段只对当天有意义；同时写上 `%%c:最初日期%%`。旧任务没有 `c` 时，`chainOrigin` 顺着前面连续几天同名的 `[>]` 往回找。视图用 `carryAge` 显示「已拖 N 天」。
2. 在本期今天的小节插入这些块；`markCarried` 把原来的行改成 `- [>]`（`carryMode = move` 时直接删掉），这样它们不会重复顺延。
   - 收集和标记在同一次 `vault.process` 里完成（上一期一次，本期一次，本期那次同时插入）。如果分成「先 read、再写」两步，中间笔记被改过时原行可能标不上，下次就会重复顺延。
   - 先处理更早的各期，再写本期。写本期失败时，`unmarkCarried` 把更早各期的改动还原，任务不会丢。
3. 记下 `settings.carry`，用于顶部提示和「顺延」标签（按 `raw` 匹配）。顺延来的任务之后被拖动、编辑、打勾时，`updateTask` / `updateMany` 会调用 `remapCarry`，把记录里的 `raw` 换成新的行文本，标签不会丢。
4. 如果有任务被移动，就先返回并重新渲染一次，显示最新内容。

### 4.5.1 时区

笔记里的日期是不带时区的「墙上时间」，所以不转换数据，只换「现在」：`zoneNow()` 用 `Intl.DateTimeFormat` 取所选时区的年月日时分秒，构造一个读数相同的本地 `moment`。代码里所有取当前时间的地方都走它，日期比较和加减不用改。当前小时用 `zoneHour()` 直接取，避开本地夏令时跳过的那一小时。

`setZone` 不写笔记。切换后「今天」变晚时记下 `carryHold`，`carryOver` 在这一天直接返回，视图用只读的 `pendingCarry` 列出待顺延任务，由用户确认（`releaseCarry`）；「今天」变早时清除 `carryHold`。否则只是点一下切换，任务就会被改到新日期，切回来也还原不了。

视图每 10 秒更新时钟，跨小时或跨天时刷新。

### 4.6 新建一期

`createPeriod(start, end, migrate)` 用 `periodProblem` 检查：结束不早于开始、起止在同一个月、和已有各期的日期不重叠。新建窗口也用同一个函数实时检查，有问题时预览变红、「创建」按钮不可点。

默认日期由 `suggestPeriod` 给出：从今天开始，落在已有的期里就跳到那一期的下一天，直到空出来；结束日用 `periodEndFor`（10 日、20 日或月末，碰到后面已有的期就停在它前一天）。

勾选迁移时，把上一期未完成的周期任务块搬到新笔记的 `{{tasks}}` 位置，并从旧笔记里删掉。`fillTemplate` 先替换 `{{day}}` 再替换 `{{tasks}}`，所以任务文字里的 `{{day}}` 不会被误换；模板里没有 `{{tasks}}` 时，任务放在 `## 周期任务` 下面，没有这一节就加在最前面，避免从旧笔记删掉了却没写进新笔记。第一天的小节：如果今天在新的一期范围内，就是今天，否则是开始日。

### 4.7 趣味动画

难点在于视图每次改动后都会整体重建 DOM。如果直接在卡片上挂动画，重建后要么动画被打断，要么每次刷新都重播一遍。处理方法分三类：

- **一次性特效放在视图外。** 粒子和彩带画在 `body > .pm-fx-layer` 上（`position: fixed`），不受重建影响，播完自己删掉。
- **用短期标记跨过重建。** 打勾时先在原来的勾选圈上立刻播弹跳，同时记下 `this.pop = { raw, until }`（raw 是完成后的行文本，2 秒内有效）。重建时，`popMatch` 对上这张卡，就补一个「勾号落定 + 淡化」的收尾动画，然后清除标记。战绩卡同理，用 `this.stats.played` 保证翻转只播一次。
- **持续动画由状态决定。** 火势 `heatOf` 是纯函数：未完成数 ÷ 2 向上取整，有今明两天截止的再加 1，结果限制在 1–3。等级写进 `data-heat`，CSS 按等级选择动画速度和颜色，重建后照样一致。「熄灭冒烟」需要知道前后变化，所以视图记下上一次的 `heatKey`（文件 + 日期）和火势；同一天里从有火变成 0，才冒 4 秒烟，换日期或第一次打开不会冒。

所有动画都在 `.pm-fx` 下才生效（`applySkin` 根据 `settings.fx` 加上这个类）。`fxOn()` 还会检查 `prefers-reduced-motion`，CSS 里也有对应的 `@media` 兜底。

### 4.8 星空背景

`skyLayout(allDaily, periodTasks, viewDay)` 是纯函数，输出 `{ stars, lines }`：

1. 取本期里已完成、有象限、日期不晚于查看日的每日任务，按日期和行号排序。
2. 每颗星的键是 `日期|文本|同名序号`。用 FNV-1a 哈希这个键作为 mulberry32 的种子，在象限内（x 6–94，y 8–92，单位是百分比）生成 6 个候选点，取离「更早日子的星星」最远的那个。只避开更早的日子，所以当天新完成的任务不会让已有的星星移动；不依赖行号，所以在笔记里增删行也不会。
3. 星星记下所属周期任务的星级（决定大小）、是否是查看日当天（闪烁）、距今几天（透明度）。
4. 同一象限、同一周期任务下有 2 颗以上星星时，按顺序连成一条折线。

视图里，每个象限的第一个子元素是 `.pm-sky`（`position: absolute`，`z-index: 0`），标题和列表提升到 `z-index: 1`。连线用一个 `viewBox="0 0 100 100"`、`preserveAspectRatio="none"` 的 SVG 画，加上 `vector-effect: non-scaling-stroke`，象限怎么拉伸线宽都不变；星星本身用 `left/top` 百分比定位的 div，所以不会被拉成椭圆。

银河用整张看板的坐标（0–1）描述：一条三次贝塞尔曲线（`GALAXY`），宽度由 `galaxyWidth(t)` 沿途起伏。`galaxyLayout` 以文件路径为种子生成几类元素，位置都用「沿河位置 t + 偏离河心距离 off」表示：大片薄雾、河心光团、3 道暗尘带、约 2200 颗小星（含 4 个星团）、16 颗亮星。`renderGalaxy` 把它们画到一张和看板一样大的离屏 canvas 上：先用 `lighter` 叠加薄雾和光团，再用 `destination-out` 挖出暗尘带，最后点上小星。这张图按看板尺寸、像素比和深浅色缓存。

每个象限的天空里有一个 `canvas.pm-galaxy`，`placeRivers()` 把离屏图按「看板左上角相对于象限的偏移」画进去，所以四块天空之间有间隙，银河却是连续的。亮星是 DOM 元素（要做闪烁动画），放在同样对齐到整张看板的 `.pm-river` 里。尺寸变化由 ResizeObserver 触发，合并到下一帧再重画。

开启星空背景时，`applySkin` 还会加上 `.pm-space`，CSS 在这个类下重写 `--pm-bg`、`--pm-surface` 等主题变量，所以卡片、日程等面板不需要逐个改写，只是变成半透明，再加 `backdrop-filter` 柔化背后的星空。整页背景是 `buildSpace()` 在视图容器里插入的 `.pm-space-bg`，放在 `.view-content` 后面（`.view-content` 的背景改为透明），不随内容滚动；里面的星星复用 `dustLayout`，和象限里的微尘由同一个 `fillDust` 生成。流星有 30% 的概率落在整页背景上。

流星特效沿用 4.7 的思路：打勾时把勾选圈的位置存进 `pop.from`；重建后，`render` 末尾的 `flyPop()` 找到对应的新星，在 `.pm-fx-layer` 上画一颗从旧位置飞向新星的光点，新星带 `is-born` 延迟 0.5 秒亮起。`pop.flown` 保证只飞一次。偶尔划过的流星是每 6 秒一次的定时器（75% 概率出现），只在深色、开启动画、页面可见时随机出现。

### 4.9 周期任务排序

卡片顺序就是笔记里的行顺序（已完成的排在最后）。在周期任务区拖动时，按阅读顺序算出插到哪张卡片前面，`moveTaskBlock` 把任务行连同备注整块挪过去。拖进象限仍然是拆出今天的子任务。

### 4.10 大模型

`chat` 用 Obsidian 的 `requestUrl` 调 DMXAPI 的 `/v1/chat/completions`（`Authorization: Bearer 密钥`），从 `choices[0].message.content` 取结果，出错时把 HTTP 状态码和 `error.message` 告诉用户。

- 回顾：`periodDigest` 把本期整理成纯文本（去掉元数据，写上状态、象限、主线、拖了几天），连同本期笔记一起交给模型。
- 出题：只发本期笔记（或单独一篇）。
- 结果用 `createNote` 存成本期笔记并打开。同一时间只跑一个请求（`aiBusy`）。

### 4.11 工作助理

`AgentView` 是右侧边栏的视图。

- **接口**：Claude 走 DMXAPI 的 `/v1/messages`（`thinking: adaptive` + `output_config.effort`，推理强度要这样传才生效），其他模型走 `/v1/chat/completions`（`reasoning_effort`）。请求由 `buildChatRequest` 构造。
- **流式**：用 `fetch` 读 SSE。`sseSplit` 切事件（不完整的最后一行留到下一块），`streamDelta` 把两种格式统一成正文、思考、用量。`fetch` 失败时退回 `requestUrl` 一次性请求。界面最多每 100ms 重画一次。
- **上下文**：每次发消息由 `agentContext` 重新生成，按开关带上今天、昨天（可能在上一期的笔记里）、本期主线、本期笔记，放进系统提示 `agentSystem`。
- **改动**：模型在回复末尾写一个 ```` ```workmap ```` JSON 块，`parseActions` 取出来显示成卡片。用户确认后由 `applyAction` 执行。它每次重新读笔记，按名字找今天的任务（`matchTask`），再走 `addDayTask` / `updateTask`，所以照样进撤销历史。执行状态写回 JSON 里的 `state`。
- **存档**：`formatChat` / `parseChat` 和 md 互转，存在本期文件夹的 `对话/` 里。简报缓存在 `data.json` 的 `brief` 里。

## 6. 设计取舍

| 决定 | 理由 | 代价 |
| --- | --- | --- |
| 单文件、不构建 | 改了就能用，没有工具链 | 文件较长（约 5300 行），类型只能靠约定 |
| 元数据放在 `%%…%%` | 不打扰阅读，标准任务语法不受影响 | 源码模式下行比较长 |
| 用坐标表示列表顺序 | 兼容旧数据；排序只改少数几行 | 频繁拖动后 y 值会被重新排开，产生更多 diff |
| 按原文定位行 | 不怕用户同时编辑 | 两行完全相同的任务只能按出现顺序区分 |
| 每次整体重建 DOM | 简单，状态不会不一致 | 任务非常多时会有一点性能开销（目前规模下可忽略） |
| 一期限定在同一个月 | 小节标题只写日（`## 19`），路径简单 | 不支持跨月的一期 |
| 自动顺延直接写文件 | 打开笔记就能看到真实状态，不依赖插件 | 会改动旧日期的小节（`- [>]` 或删除） |
| 本期笔记存成单独文件 | 笔记里的标题不影响时段笔记；单篇也能出题 | 多了一个文件夹 |
| 大模型结果不流式输出 | 实现简单，结果直接存成笔记 | 要等半分钟到两分钟 |
